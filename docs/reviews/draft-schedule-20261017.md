# 取消後の差し替え下書きの公開予約

原因：`replace-cancelled` は必ず draft を保存する一方、既存 UI の編集・日時変更は公開1時間前で非表示になる。通常投稿には下書きを公開予約する独立した操作がなく、同日新規作成も slot の一意制約で拒否される。

基点：`feat/owner-video-upload` の `75bf7238ad2db001f7dfadda2058f50c81817987`。main は旧版のため、この差分だけを main に適用しないこと。

修正：通常投稿の未処理 draft に「内容を確認して公開予約」を追加。最新の保存素材（動画なら再生可能）、本文、JST日時を表示し、チェック後に1回だけ送信。同じJST日付内の1分後以降に予約できる。既存ID・slot・assetを保持する。日時変更は確認チェックを解除し、中止では書き込まない。通信結果が不明でも自動再送せず status を読戻し、内容と予約状態が一致した場合だけ成功表示する。

APIは tick ロック内で draft/feed、未処理、更新版、素材IDを検証。保存素材を既存JPEG/MP4検査・本文検査・未完成フラグ/ハッシュ検査に通し、予約と監査記録をトランザクションで保存する。取消、公開済み、結果不明、処理中、コンテナ等の痕跡がある状態は拒否する。天気ストーリーの日時・順序・公開処理は変更しない。

検証：`npm test` 96件合格（実通信禁止の模擬DB/API）。`node scripts/check-media-upload-ui.mjs` 合格（全リクエストをオフラインで応答するChromium）。新規ケース：取消→新動画下書き→1時間以内の予約、16時後から同日17時への遅延予約、古い版、連打、中止、取消後の再操作、通信中断後の読戻し、不正動画/素材欠落/未完成素材、ロック競合、監査失敗時のロールバック、未認証拒否。既存動画検証・複数ストーリー順序・結果不明時停止も全件合格。
